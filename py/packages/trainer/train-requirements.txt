# SFT training stack for `assayops_trainer.sft.run_sft` (#176 leg 2) -- Qwen2.5-Coder-7B SFT+LoRA.
#
# Intentionally NOT a workspace dependency: torch + the HF training stack would force the hermetic
# `bun run verify` gate to resolve CUDA wheels on every run. These live here instead and are
# lazy-imported by sft.py, so the gate stays fast and torch-free.
#
# I8 (pin everything): the lower bounds below are the MINIMUMS this harness targets. Before a real
# run, freeze exact, hash-locked versions in the GPU training env
# (`uv pip compile --generate-hashes`) AND pin the model revision (TrainerConfig.model_revision) --
# a directional lift number is only reproducible against a pinned stack + model.
#
# Validated baseline (config kwargs run through the real SFTConfig/LoraConfig constructors):
#   trl 1.7.0 · peft 0.19.1 · transformers 5.12.1 · datasets 5.0.0 · accelerate 1.14.0 · torch 2.12.1
# TrainerConfig targets the current SFTConfig API: `max_length` (NOT the pre-refactor
# `max_seq_length`) + `assistant_only_loss`. The trl floor is >=1.7 to guarantee that API -- earlier
# lines may still use `max_seq_length` and would break run_sft. assistant_only_loss (masking tool
# observations at train time): Qwen2.5's stock template has no `{% generation %}` markers; trl 1.7
# swaps in its VENDORED Qwen2.5 training template when the tokenizer's template byte-equals the
# stock one, and fails LOUD otherwise (ValueError at init on an unrecognized template; RuntimeError
# on an example with an empty assistant mask). run_sft loads the model AND the tokenizer itself at
# model_revision (a model string would leave trl's AutoConfig probe + processor on `main`) so that
# byte-match is stable.
# The transformers/datasets/accelerate floors are trl 1.7.0's OWN minimums (anything lower is
# unresolvable next to trl>=1.7); peft's floor is peft's own API line.
trl>=1.7
peft>=0.13
transformers>=4.56.2
datasets>=4.7
accelerate>=1.4
torch>=2.4
